# Documentation i18n convention

KoiosBase documents are maintained in parallel translations. The root
`README.md` is English and is the only file GitHub renders automatically — every
other translation lives under `i18n/` and is reached from the switcher line.

## Layout

```
README.md              English — the default landing page, always present
i18n/README.<lang>.md  one file per other language
docs/i18n.md           this convention
```

Defaulting to one English file at the root and grouping the rest under `i18n/`
keeps the repository root readable while making "which languages exist" a single
directory listing.

## Current languages

| Language | Code | File |
| --- | --- | --- |
| English (default) | — | `README.md` |
| 简体中文 | `zh` | `i18n/README.zh.md` |
| 日本語 | `ja` | `i18n/README.ja.md` |

Design docs keep their descriptive name. A translation adds the language code
before the extension: `KoiosBase设计文档v1.3.md` → `docs/KoiosBase设计文档v1.3.en.md`

## Language switcher

Every README — including the English one — opens with the same line, so a reader
can change language from any entry point:

```markdown
[English](README.md) | [中文](i18n/README.zh.md) | [日本語](i18n/README.ja.md)
```

## Rules

1. **Same sections, same order.** A reader comparing two languages must be able
   to line them up. If a section is added in one, add it in all.
2. **Never invent facts in translation.** Translate what the code actually does.
   If a section claims a feature, that feature must exist — the "known gaps"
   sections exist precisely so translations can stay honest.
3. **Code, paths, CLI flags and design references stay untranslated.**
   `koios index`, `raw/`, `§8.3` are identifiers, not prose.
4. **English is authoritative on ambiguity.** If two translations disagree about
   behaviour, the code wins; if they disagree about wording only, English wins.

## Adding a language

1. Copy `README.md` to `i18n/README.<lang>.md` (lowercase ISO 639-1 code).
2. Translate prose; leave code blocks, paths and flags alone.
3. Add the new link to the switcher line in **every** README, including English.
4. Update the table above.
