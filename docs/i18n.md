# Documentation i18n convention

KoiosBase documents are maintained in parallel translations. The root
`README.md` is English and is the only file GitHub renders automatically — every
other translation lives under `docs/i18n/` and is reached from the switcher line.

## Layout

```
README.md                   English — the default landing page, always present
docs/i18n/README.<lang>.md  one file per other language
docs/i18n.md                this convention
```

Defaulting to one English file at the root and grouping the rest under `docs/i18n/`
keeps the repository root readable while making "which languages exist" a single
directory listing.

## English is the source of truth; translations may lag

`README.md` is authoritative. Translations under `docs/i18n/` mirror it, but they are
**allowed to fall behind** while it is being restructured — a stale translation
is worse than a missing one only if it silently claims to describe current
behaviour.

Practical consequence: **the switcher line stays in every README even when its
content is out of date**, so a reader can always reach English and see the real
state. Syncing a translation means copying the English code blocks and example
output verbatim and translating only prose.

## Naming table

| Language | Code | File |
| --- | --- | --- |
| English (default) | — | `README.md` |
| 简体中文 | `zh` | `docs/i18n/README.zh.md` |
| 日本語 | `ja` | `docs/i18n/README.ja.md` |

Design docs keep their descriptive name. A translation adds the language code
before the extension: `KoiosBase设计文档v1.3.md` → `docs/KoiosBase设计文档v1.3.en.md`.

## Language switcher

Every README — including the English one — opens with the same line, so a reader
can change language from any entry point. The links are relative to the file the
line sits in, so the two forms differ:

```markdown
# README.md (root — English is this file, siblings are under docs/i18n/)
[English](README.md) | [中文](docs/i18n/README.zh.md) | [日本語](docs/i18n/README.ja.md)

# docs/i18n/README.<lang>.md (translations — English is two levels up)
[English](../../README.md) | [中文](README.zh.md) | [日本語](README.ja.md)
```

## Rules

1. **Same sections, same order — when synced.** A reader comparing two languages
   must be able to line them up. A translation may lag behind a restructure
   (see above), but once synced it matches section for section.
2. **Never invent facts in translation.** Translate what the code actually does.
   If a section claims a feature, that feature must exist — the "known gaps"
   sections exist precisely so translations can stay honest.
3. **Code, paths, CLI flags and design references stay untranslated.**
   `koios index`, `raw/`, `§8.3` are identifiers, not prose.
4. **English is authoritative on ambiguity.** If two translations disagree about
   behaviour, the code wins; if they disagree about wording only, English wins.

## Adding a language

1. Copy `README.md` to `docs/i18n/README.<lang>.md` (lowercase ISO 639-1 code).
2. Translate prose; leave code blocks, paths and flags alone.
3. Add the new link to the switcher line in **every** README, including English.
4. Update the table above.
