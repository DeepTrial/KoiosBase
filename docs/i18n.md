# Documentation i18n convention

KoiosBase documents are maintained in parallel translations. The English file is
the source of truth for *structure*; every other language mirrors it section by
section.

## Current languages

| Language | Suffix | README | Docs |
| --- | --- | --- | --- |
| English | none | `README.md` | — |
| 简体中文 | `.zh` | `README.zh.md` | `docs/KoiosBase设计文档v1.3.md` |
| 日本語 | `.ja` | `README.ja.md` | — |

## File naming

- `README.md` — English (default landing page for GitHub)
- `README.<lang>.md` — other languages, `<lang>` is a lowercase ISO 639-1 code
- Design docs keep their descriptive name; a translation adds the suffix before
  the extension: `KoiosBase设计文档v1.3.md` → `KoiosBase设计文档v1.3.en.md`

## Language switcher

Every translated README opens with the same switcher line, so the reader can move
between languages from any entry point:

```markdown
[English](README.md) | [中文](README.zh.md) | [日本語](README.ja.md)
```

## Rules

1. **Same sections, same order.** A reader comparing two languages must be able
   to line them up. If a section is added in one, add it in all.
2. **Never invent facts in translation.** Translate what the code actually does.
   If a section claims a feature, that feature must exist — see the "known gaps"
   sections, which exist precisely so translations stay honest.
3. **Code, paths, CLI flags and design references stay untranslated.**
   `koios index`, `raw/`, `§8.3` are identifiers, not prose.
4. **English is authoritative on ambiguity.** If two translations disagree about
   behaviour, the code wins; if they disagree about wording only, English wins.

## Adding a language

1. Copy `README.md` to `README.<lang>.md`.
2. Translate prose; leave code blocks, paths and flags alone.
3. Add the new link to the switcher line in **every** README (including English).
4. Update the table in this file.
